Why FalkorDB for AI engagements, and more

RAG finds similar text. Real questions need connected facts. Cortex turns 73 bank documents into a knowledge graph in FalkorDB and answers the same questions two ways: plain vector RAG and GraphRAG. Then it shows what else the graph can do.

2 · Why FalkorDB is fast: how it stores a graph

Sparse matrices, not pointer chasing. Each relationship type is stored as a sparse adjacency matrix (GraphBLAS). A multi-hop traversal becomes matrix multiplication, which is why 2-hop GraphRAG expansion and fraud-ring detection stay in milliseconds.
Graph + vector in one engine. Chunk embeddings live on graph nodes with an HNSW vector index. Vector search and graph expansion run in the same query language, in the same process, with no second database to sync.
Many graphs, one instance. The bank knowledge graph, the 1M-node operational graph and every tester's upload sandbox are separate graphs in one server. A sandbox wipe is one GRAPH.DELETE.
In-memory and embeddable. FalkorDB is a Redis module. Here it runs embedded inside the Space container: no managed database, no network hop, $0. It speaks OpenCypher, so queries read like Neo4j's.
